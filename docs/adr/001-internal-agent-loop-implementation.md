## Проблема

Сейчас обработка запроса идет в 3 этапа: планирование (LLM), сбор информации при помощи data providers, ответ (LLM). 
Эта цепочка плохо работает когда вопрос требует аналитики данных так как полный объем нужных данных не известен заранее 
и не может быть точно определн на этапе планирования за один раз. Также данный подход делает не возможным уточнение 
какой-либо информации как у пользователя (на стороне Miranda) так и у медкарты (если пользователь задает вопрос 
на основании полученно от медкарты ответа). 

## Идея:

Нужно реализовать внутри сервиса «Медкарта» полноценный **agent loop** с хранением истории сесии где в качестве 
assistant выступает LLM, а в качестве user выступает пользователь со стороны Миранды (или сама Миранда). 

### 1. Архитектура агента

«Медкарта» должна иметь собственный LLM-agent, который работает исключительно с контекстом и данными медкарты и самостоятельно принимает решения о том:

- какие данные необходимо получить;
- какие Data Provider / MCP tools вызвать;
- нужно ли сделать дополнительные вызовы;
- достаточно ли полученных данных для формирования ответа.

Один пользовательский запрос может требовать **нескольких последовательных обращений к Data Provider'ам**. Агент должен иметь возможность итеративно получать дополнительные данные до тех пор, пока не сможет сформировать обоснованный ответ.

Не ограничивать обработку одним LLM → tool → response проходом.

### 2. Сессии и follow-up вопросы

Необходимо поддержать полноценные пользовательские сессии, аналогично механизму сессий в Miranda.
Идентификатор сессии можно запрашивать через MCP как параметр и Миранда передаст свой ID текущей сессии, что
гарантирует консистентность между сессией реального пользователя и сессией внутри медкарты.

После получения ответа пользователь должен иметь возможность:

- задать уточняющий вопрос;
- запросить дополнительные сведения;
- продолжить обсуждение на основании предыдущего ответа.

Agent должен сохранять необходимый контекст сессии между запросами.

### 3. Интеграция с Miranda

Miranda не должна знать внутреннюю архитектуру или логику «Медкарты».

При вызове MCP-тулa «Медкарты» Miranda должна:

1. передать пользовательский вопрос в «Медкарту»;
2. получить готовый ответ от agent'а «Медкарты»;
3. передать этот ответ пользователю **без изменения смысла, дополнительной интерпретации или переработки содержания**.

Таким образом, «Медкарта» является самостоятельным специализированным агентом, а Miranda — только интерфейсом/маршрутизатором для взаимодействия с ним.
