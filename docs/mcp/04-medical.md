# 1. Назначение

`medical.ask` является главным MCP Tool Medical Service.

Именно через него Miranda получает экспертные ответы на медицинские вопросы пользователя.

В отличие от остальных MCP Tool, данный инструмент не предоставляет доступ к данным напрямую.

Он самостоятельно:

- понимает вопрос пользователя;
- определяет необходимые источники знаний;
- собирает медицинский контекст;
- анализирует информацию;
- формирует итоговый ответ.

Для Miranda этот процесс полностью прозрачен.

---

# 2. Основная идея

Medical Service рассматривается как медицинский эксперт.

Miranda не анализирует медицинские данные самостоятельно.

Вместо этого она делегирует вопрос специалисту.

```text
User

↓

Miranda

↓

medical.ask()

↓

Medical Expert

↓

Answer
```

---

# 3. Ответственность Tool

`medical.ask` отвечает за:

- понимание вопроса;
- выбор необходимых Knowledge Providers;
- поиск информации;
- анализ медицинских данных;
- построение логических выводов;
- генерацию понятного ответа.

Все перечисленные этапы выполняются внутри сервиса.

---

# 4. Что НЕ делает Miranda

Miranda никогда не должна:

- искать документы;
- выбирать анализы;
- определять нужные лекарства;
- анализировать лабораторные показатели;
- искать события Timeline;
- объединять медицинские данные;
- выполнять медицинские выводы.

Единственная задача Miranda — передать вопрос пользователя.

# 7. Внутренний Pipeline

```text
Question

↓

Planner

↓

Knowledge Providers

↓

Search

↓

Context Builder

↓

Answer Generator

↓

Answer
```

Весь Pipeline является внутренней реализацией сервиса.

Miranda ничего не знает о его существовании.

---

# 8. Planner

Первым этапом является Planner.

Он определяет:

- какие Knowledge Providers необходимо использовать;
- какие данные потребуется получить;
- какие части медицинской истории относятся к вопросу.

Planner никогда не отвечает пользователю.

---

# 9. Knowledge Providers

После построения плана запускаются соответствующие Providers.

Например.

Вопрос:

> Почему врач отменил статины?

Могут быть использованы:

- Timeline Provider;
- Medication Provider;
- Lab Provider;
- Document Provider.

При этом Miranda ничего не знает о выборе источников.

---

# 10. Формирование ответа

После завершения работы Providers сервис получает структурированный медицинский контекст.

Только после этого вызывается LLM для генерации ответа.

Таким образом модель никогда не анализирует документы напрямую.

Она работает исключительно с уже подготовленными знаниями.

---

# 11. Ограничения

Если необходимая информация отсутствует в базе знаний, сервис должен честно сообщить об этом.

Например:

> В медицинской истории нет информации о данном заболевании.

или

> Не удалось найти документы за указанный период.

LLM не должна придумывать отсутствующие факты.

---

# 12. Использование Timeline

Практически любой медицинский вопрос имеет временной контекст.

Поэтому Timeline является одним из наиболее часто используемых Knowledge Providers.

Например.

> Что происходило после операции?

> Когда начали принимать препарат?

> Что изменилось летом прошлого года?

Все подобные вопросы решаются через Timeline.

---

# 13. Использование Profile

При вопросах о текущем состоянии здоровья автоматически используется Medical Profile.

Например.

> Какие лекарства я сейчас принимаю?

> Какие хронические заболевания у меня есть?

> Какие аллергии известны?

Использование агрегированного профиля позволяет избежать анализа всей истории болезни.

---

# 14. Источники знаний

Во время обработки вопроса сервис может использовать одновременно:

- Timeline;
- Medical Profile;
- Medications;
- Diagnoses;
- Procedures;
- Lab Results;
- Documents;
- Embeddings.

Выбор источников полностью определяется Planner.

---

# 15. Производительность

Каждый Provider работает независимо.

Если требуется несколько источников знаний, они выполняются параллельно.

После завершения результаты объединяются в единый контекст.

---

# 16. Ответ

Ответ формируется специально для пользователя.

Он должен быть:

- понятным;
- структурированным;
- основанным на найденных данных;
- не содержать необоснованных предположений.

При необходимости сервис должен указывать источник своих выводов.

Например:

> Согласно результатам анализа крови от 12 марта 2025 года...

или

> В выписке после госпитализации указано...

---

# 17. Чего не гарантирует Tool

`medical.ask` не предоставляет медицинских рекомендаций, выходящих за пределы известных сервису данных.

Он не заменяет врача.

Если вопрос требует профессиональной диагностики, сервис должен явно указать на это.

Например:

> По имеющимся документам невозможно определить причину повышения ALT. Для интерпретации результатов рекомендуется обсудить их с лечащим врачом.

---

# 18. Архитектурные решения

`medical.ask` является единственной точкой входа для интеллектуального анализа медицинской информации.

Это позволяет:

- изменять внутренний Pipeline;
- заменять модели LLM;
- добавлять новые Knowledge Providers;
- изменять алгоритмы поиска;
- совершенствовать медицинскую модель.

Все эти изменения происходят без изменения MCP API.

---

# 19. Будущие расширения

В будущем возможности `medical.ask` могут быть расширены без изменения интерфейса.

Например:

- анализ изображений, приложенных к вопросу;
- учет информации из других сервисов Miranda (питание, сон, фитнес);
- построение долгосрочных трендов;
- сравнение показателей за разные периоды;
- объяснение медицинских терминов;
- анализ лекарственных взаимодействий;
- использование специализированных медицинских моделей.

Все эти возможности должны оставаться внутренней реализацией сервиса и не изменять внешний контракт MCP Tool.
