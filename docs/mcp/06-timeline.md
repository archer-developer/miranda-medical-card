# 1. Назначение

`medical.timeline` возвращает хронологическую последовательность медицинских событий пользователя.

Timeline представляет собой единое представление истории болезни независимо от того, из каких документов были получены данные.

Инструмент предназначен для:

- построения пользовательского интерфейса;
- визуализации истории болезни;
- навигации по медицинской истории;
- быстрого просмотра событий за выбранный период.

В отличие от `medical.ask`, Timeline не анализирует события и не делает медицинских выводов.

Он возвращает только структурированные данные.

---

# 2. Что такое медицинское событие

Timeline состоит из независимых медицинских событий.

Каждое событие представляет факт, произошедший в определённый момент времени.

Например:

- лабораторное исследование;
- посещение врача;
- постановка диагноза;
- назначение лекарства;
- отмена лекарства;
- операция;
- госпитализация;
- вакцинация;
- изменение жизненных показателей;
- получение медицинского документа.

Все события автоматически извлекаются во время обработки документов.

---

# 3. Когда использовать

Используйте `medical.timeline`, если необходимо:

- показать медицинскую историю;
- построить временную шкалу;
- показать события за определённый период;
- реализовать навигацию по истории болезни.

Если требуется анализ событий, следует использовать `medical.ask`.

---

# 4. Интерфейс

## Параметры

| Поле | Тип | Обязательно | Описание |
|------|-----|-------------|----------|
| `userId` | string | ✅ | Идентификатор пользователя |
| `subjectId` | string | ❌ | Чью историю получить, если не свою — см. `01-overview.md` §11 |
| `from` | date | ❌ | Начало периода |
| `to` | date | ❌ | Конец периода |
| `types` | string[] | ❌ | Фильтр по типам событий |
| `limit` | integer | ❌ | Максимальное количество событий |

Все параметры являются фильтрами и не влияют на структуру ответа.

---

# 5. Ответ

```json
{
  "events": [
    {
      "eventId": "evt_01J...",
      "date": "2025-03-12",
      "type": "lab_result",
      "title": "Общий анализ крови",
      "summary": "Выявлено небольшое повышение ALT.",
      "documentId": "doc_01J..."
    }
  ]
}
```

Ответ содержит только краткую информацию, необходимую для отображения Timeline.

---

# 6. Типы событий

Перечень типов событий не является закрытым.

Наиболее распространённые типы:

- `consultation`
- `diagnosis`
- `procedure`
- `hospitalization`
- `surgery`
- `medication_started`
- `medication_changed`
- `medication_stopped`
- `lab_result`
- `vaccination`
- `vital_sign`
- `document`
- `symptom`
- `medication_taken`

`symptom` и `medication_taken` — единственные типы, порождаемые не из документа, а из `medical.log_event` (см. `07-events.md`); соответствующие события не содержат `documentId` (см. §10).

Новые типы могут добавляться без изменения MCP API.

---

# 7. Фильтрация

Timeline может быть ограничен по периоду.

Например:

```json
{
  "from": "2025-01-01",
  "to": "2025-12-31"
}
```

Или по типу событий:

```json
{
  "types": [
    "lab_result",
    "consultation"
  ]
}
```

Фильтры могут использоваться совместно.

---

# 8. Сортировка

События всегда возвращаются в хронологическом порядке.

По умолчанию используется сортировка от новых событий к старым (descending).

Порядок сортировки может быть расширен в будущих версиях сервиса при необходимости.

---

# 9. Summary

Каждое событие содержит краткое описание.

Summary предназначен исключительно для отображения пользователю.

Например:

> Назначен Rosuvastatin 10 мг ежедневно.

или

> Общий анализ крови. Незначительное повышение ALT.

Summary не должен содержать медицинских выводов или интерпретации результатов.

---

# 10. Связь с документами

Большинство событий связано с медицинским документом.

В этом случае возвращается:

```json
{
    "documentId": "doc_..."
}
```

Miranda может использовать `medical.get_document`, чтобы получить информацию об исходном документе.

События типов `symptom` и `medication_taken` (см. §6) не связаны ни с каким документом — поле `documentId` у них отсутствует, поскольку они порождены `medical.log_event`, а не Documents API (см. `07-events.md`).

---

# 11. Timeline как производная сущность

Timeline не редактируется напрямую.

Он автоматически перестраивается после:

- импорта документа;
- удаления документа.

Все изменения происходят внутри Processing Pipeline.

---

# 12. Производительность

Timeline является материализованной проекцией медицинской истории.

Для получения списка событий не требуется повторный анализ документов.

Это делает инструмент быстрым и предсказуемым.

---

# 13. Использование внутри Medical Service

Во время обработки вопросов `medical.ask` Timeline используется как один из основных Knowledge Providers.

Например:

> Что происходило прошлой зимой?

> Когда начали принимать бисопролол?

> Что было после операции?

В этих случаях Planner может получить данные непосредственно из Timeline.

---

# 14. Ограничения

Timeline не предназначен для:

- медицинского анализа;
- поиска причин;
- объяснения изменений;
- сравнения анализов;
- построения выводов.

Эти задачи выполняет `medical.ask`.

---

# 15. Идентификаторы событий

Каждое событие имеет собственный `eventId`.

Идентификатор является стабильным и может использоваться пользовательским интерфейсом, например:

- для навигации;
- выделения события;
- открытия карточки события;
- сохранения состояния интерфейса.

---

# 16. Архитектурные решения

Timeline является материализованным представлением медицинской истории.

Он:

- автоматически поддерживается в актуальном состоянии;
- не редактируется вручную;
- не является источником истины;
- оптимизирован для чтения.

Источником истины всегда остаются структурированные медицинские сущности, извлечённые из документов.

# 18. Будущие расширения

В будущем Timeline может быть дополнен без изменения существующего интерфейса.

Например:

- группировка по дням, месяцам или годам;
- отображение связанных событий;
- ссылки на изображения и вложения;
- отметки важных событий;
- пользовательские заметки;
- цветовые категории;
- источники данных (Apple Health, Garmin и др.);
- объединение событий из нескольких сервисов Miranda.

Все расширения должны сохранять основную идею Timeline — быть структурированным хронологическим представлением медицинской истории без выполнения анализа.
